## 서론

디자인 패턴은 소프트웨어 개발에서 자주 발생하는 문제들에 대한 재사용 가능한 해결책입니다. 이는 경험 많은 개발자들이 오랜 시간 동안 발견하고 정제한 best practice들의 집합이라고 할 수 있습니다. 디자인 패턴을 이해하고 적절히 활용하면, 더 유연하고 재사용 가능하며 유지보수가 용이한 소프트웨어를 개발할 수 있습니다.

## 디자인 패턴의 중요성

1. **재사용성**: 검증된 솔루션을 재사용하여 개발 시간을 단축할 수 있습니다.
2. **가독성**: 패턴을 아는 개발자들 사이에서 코드의 의도를 쉽게 이해할 수 있게 합니다.
3. **유지보수성**: 잘 구조화된 코드는 수정과 확장이 쉽습니다.
4. **확장성**: future의 요구사항 변경에 대비할 수 있습니다.
5. **커뮤니케이션**: 개발자들 사이의 의사소통을 돕는 공통 언어를 제공합니다.
6. **best practice**: 많은 개발자들의 경험이 녹아있는 검증된 솔루션을 활용할 수 있습니다.
7. **추상화**: 복잡한 시스템을 더 이해하기 쉬운 작은 단위로 나눌 수 있습니다.

## 생성 패턴 (Creational Patterns)

생성 패턴은 객체 생성 메커니즘을 다룹니다. 이 패턴들은 상황에 맞는 객체를 유연하게 생성할 수 있도록 돕습니다.

### 싱글톤 패턴 (Singleton)

- **목적**: 클래스의 인스턴스가 오직 하나만 생성되도록 보장합니다.
- **사용 시기**: 전역적으로 사용되는 객체가 하나만 필요할 때 (예: 설정 관리자, 로깅 시스템)
- **장점**: 
  - 전역 접근 지점을 제공합니다.
  - 객체 생성을 제어할 수 있습니다.
- **단점**: 
  - 단일 책임 원칙을 위반할 수 있습니다.
  - 테스트하기 어려울 수 있습니다.

```dart
class Singleton {
  static final Singleton _instance = Singleton._internal();

  factory Singleton() {
    return _instance;
  }

  Singleton._internal();

  void someBusinessLogic() {
    // ...
  }
}

void main() {
  var s1 = Singleton();
  var s2 = Singleton();
  print(identical(s1, s2));  // true
}
```

### 팩토리 메서드 패턴 (Factory Method)

- **목적**: 객체 생성을 서브클래스에 위임합니다.
- **사용 시기**: 객체 생성 로직이 복잡하거나, 객체의 타입이 런타임에 결정될 때
- **장점**: 
  - 객체 생성 코드를 중앙화할 수 있습니다.
  - 새로운 타입의 객체를 쉽게 추가할 수 있습니다.
- **단점**: 
  - 클래스 수가 늘어날 수 있습니다.

```dart
abstract class Product {
  void operation();
}

class ConcreteProductA implements Product {
  @override
  void operation() {
    print('ConcreteProductA operation');
  }
}

class ConcreteProductB implements Product {
  @override
  void operation() {
    print('ConcreteProductB operation');
  }
}

abstract class Creator {
  Product factoryMethod();
  
  void someOperation() {
    var product = factoryMethod();
    product.operation();
  }
}

class ConcreteCreatorA extends Creator {
  @override
  Product factoryMethod() {
    return ConcreteProductA();
  }
}

class ConcreteCreatorB extends Creator {
  @override
  Product factoryMethod() {
    return ConcreteProductB();
  }
}

void main() {
  Creator creator = ConcreteCreatorA();
  creator.someOperation();  // ConcreteProductA operation

  creator = ConcreteCreatorB();
  creator.someOperation();  // ConcreteProductB operation
}
```

### 추상 팩토리 패턴 (Abstract Factory)

- **목적**: 관련된 객체들의 family를 생성하기 위한 인터페이스를 제공합니다.
- **사용 시기**: 여러 제품군의 객체들을 생성해야 하고, 이들이 함께 동작해야 할 때
- **장점**: 
  - 제품군 간의 일관성을 보장합니다.
  - 구체적인 클래스에 대한 의존성을 제거합니다.
- **단점**: 
  - 새로운 종류의 제품을 추가하기 어려울 수 있습니다.

```dart
abstract class Button {
  void paint();
}

abstract class Checkbox {
  void paint();
}

class WinButton implements Button {
  @override
  void paint() {
    print('Windows Button');
  }
}

class MacButton implements Button {
  @override
  void paint() {
    print('Mac Button');
  }
}

class WinCheckbox implements Checkbox {
  @override
  void paint() {
    print('Windows Checkbox');
  }
}

class MacCheckbox implements Checkbox {
  @override
  void paint() {
    print('Mac Checkbox');
  }
}

abstract class GUIFactory {
  Button createButton();
  Checkbox createCheckbox();
}

class WinFactory implements GUIFactory {
  @override
  Button createButton() {
    return WinButton();
  }

  @override
  Checkbox createCheckbox() {
    return WinCheckbox();
  }
}

class MacFactory implements GUIFactory {
  @override
  Button createButton() {
    return MacButton();
  }

  @override
  Checkbox createCheckbox() {
    return MacCheckbox();
  }
}

void main() {
  GUIFactory factory = WinFactory();
  Button button = factory.createButton();
  Checkbox checkbox = factory.createCheckbox();
  button.paint();  // Windows Button
  checkbox.paint();  // Windows Checkbox

  factory = MacFactory();
  button = factory.createButton();
  checkbox = factory.createCheckbox();
  button.paint();  // Mac Button
  checkbox.paint();  // Mac Checkbox
}
```

### 빌더 패턴 (Builder)

- **목적**: 복잡한 객체의 생성 과정을 단계별로 분리합니다.
- **사용 시기**: 객체 생성 과정이 복잡하고 여러 단계를 거쳐야 할 때
- **장점**: 
  - 객체 생성 과정을 더 세밀하게 제어할 수 있습니다.
  - 같은 생성 과정으로 서로 다른 표현을 만들 수 있습니다.
- **단점**: 
  - 각 객체마다 별도의 ConcreteBuilder를 만들어야 할 수 있습니다.

```dart
class Product {
  List<String> parts = [];

  void add(String part) {
    parts.add(part);
  }

  void show() {
    print('Product Parts: ${parts.join(', ')}');
  }
}

abstract class Builder {
  void buildPartA();
  void buildPartB();
  void buildPartC();
  Product getResult();
}

class ConcreteBuilder implements Builder {
  Product _product = Product();

  @override
  void buildPartA() {
    _product.add('Part A');
  }

  @override
  void buildPartB() {
    _product.add('Part B');
  }

  @override
  void buildPartC() {
    _product.add('Part C');
  }

  @override
  Product getResult() {
    return _product;
  }
}

class Director {
  Builder _builder;

  Director(this._builder);

  void construct() {
    _builder.buildPartA();
    _builder.buildPartB();
    _builder.buildPartC();
  }
}

void main() {
  Builder builder = ConcreteBuilder();
  Director director = Director(builder);

  director.construct();
  Product product = builder.getResult();
  product.show();  // Product Parts: Part A, Part B, Part C
}
```

### 프로토타입 패턴 (Prototype)

- **목적**: 기존 객체를 복제하여 새로운 객체를 생성합니다.
- **사용 시기**: 객체 생성 비용이 높거나, 비슷한 객체를 여러 번 생성해야 할 때
- **장점**: 
  - 복잡한 객체를 효율적으로 생성할 수 있습니다.
  - 객체 생성 세부 사항을 클라이언트로부터 숨길 수 있습니다.
- **단점**: 
  - 순환 참조가 있는 복잡한 객체를 복제하기 어려울 수 있습니다.

```dart
abstract class Prototype {
  Prototype clone();
}

class ConcretePrototype implements Prototype {
  String field;

  ConcretePrototype(this.field);

  @override
  Prototype clone() {
    return ConcretePrototype(field);
  }

  @override
  String toString() {
    return 'ConcretePrototype: $field';
  }
}

void main() {
  var prototype = ConcretePrototype('Test');
  var clone = prototype.clone();
  print(prototype);  // ConcretePrototype: Test
  print(clone);  // ConcretePrototype: Test
  print(identical(prototype, clone));  // false
}
```
